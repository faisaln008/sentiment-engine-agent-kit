## Blocking
- **B1** `apps/backend/src/llm/openai-adapter.ts:57-64` — every HTTP 400 treated as "response_format unsupported"; a 2xx retry then disables JSON mode for the process. Groq returns `400 json_validate_failed` for invalid/truncated JSON-mode output (gpt-oss `finish_reason:length`) — that's bad_json, not a capability rejection. First truncated generation (possibly the warm-up) causes a second round trip inside the deadline and silently turns JSON mode off. CP1 LLM numbers likely measured in that state. Fix: retry only when the 400 body names `response_format`/`json_object`/`json mode` and code ≠ `json_validate_failed`; map `json_validate_failed` → `bad_json` with one call; disable JSON mode only if retry is 2xx and parses. Tests: `adapter.json-validate-failed-is-bad-json` (1 call; next request still sends response_format), generic 400 → `http` no retry. Rerun the LLM quick bench.

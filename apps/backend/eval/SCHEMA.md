# Eval dataset schema (JSONL, one chunk per line)

```jsonc
{
  "session_id": "s07_saas_renewal",
  "chunk_id": "s07_c04",
  "timestamp_ms": 1760000004000,          // monotonic within a session
  "speaker": "counterpart",               // candidate | counterpart
  "text": "Sure, a 30% uplift is totally reasonable for a product that went down twice last quarter.",
  "acoustic_metadata": { "pitch_volatility": 0.71, "speech_rate_wpm": 142, "pause_duration_ms": 900, "volume_intensity": 0.38 },

  "expected_sentiment": "sarcastic",
  "acceptable_sentiments": ["sarcastic", "negative"],   // lenient scoring
  "expected_risk": "high",                               // ordinal; MAE reported
  "expected_volatility": false,
  "tags": ["contradiction:text-pos/meaning-neg", "pricing", "context-dependent"],
  "pair_id": null,                                       // set for counterfactual pairs
  "rationale": "Positive surface words contradict the outage reference; long pause + elevated pitch vs. this speaker's baseline."
}
```

Rules
- Sessions are replayed **in order**; context matters. Each file = one split (`datasets/tune.jsonl`, `datasets/holdout.jsonl`).
  A session lives in exactly one file (split by session, never by chunk). Holdout is never used for prompt tuning.
- Every line = a valid `TelemetryRequestWireSchema` body + the label fields above (strict: no other keys).
  In the dataset all four acoustic fields are **required** so per-speaker baselines are exercised.
- `timestamp_ms` strictly increasing within a session (file order = replay order). `chunk_id` globally unique (`sNN_cMM`).
- Labels follow `.claude/skills/nuance-taxonomy` §1/§5. `acceptable_sentiments` always contains `expected_sentiment`.
- `expected_risk` respects the fusion floors (aggressive ⇒ ≥ high; aggressive + volatility ⇒ critical; positive ⇒ ≤ medium).
- `expected_volatility` is a **human judgement** of what a copilot should alert on, never derived from the formula:
  `true` for (a) an abrupt escalation (marked delivery spike vs. this speaker's baseline toward hostility) or
  (b) a one-turn stance flip from cooperative/conciliatory to hostile (aggressive/sarcastic), even with flat delivery;
  `false` for recoveries into calm agreement and for steady hostility. The validator replays the ADR-003 formula over
  the expected labels (`eval/lib/volatility-oracle.ts`) and prints a **formula vs label disagreements** table as WARN only:
  disagreements are allowed and are evidence for ADR-003, not label errors. Labels are never edited to match the formula.
- S2b reports volatility twice, separately: **detection** P/R/F1 (API `volatility_flag` vs. human labels) and
  **fusion fidelity** (API `volatility_flag` vs. the oracle replayed over the *returned* sentiments + acoustics).
  The oracle-vs-label agreement on expected labels is the formula's ceiling; tune ADR-003 weights on `tune` only.
- `pair_id` links chunks with **identical `text`**; both members are in the same split. Tag `counterfactual` = same text
  and context, different acoustics (mirror sessions); tag `context-flip` = same text, different previous turns.
- Labels are written **before** the model is run on them; label edits need a rationale + PROMPT_CHANGELOG note.
- Coverage matrix is regenerated by `run-eval.ts` and printed at the top of every report.
- `fixtures/sample-chunk.json` = one valid request body used by smoke tests and `/ship`.

Tag vocabulary (free-form, but these are counted by the validator / report)
- `smoke` — the 15-chunk smoke subset; always whole sessions (context intact), tune split only.
- `acoustic:agree` / `acoustic:contradict` — delivery (vs. this speaker's baseline) agrees with / contradicts the surface words.
- `contradiction:<what>` — nuance-subset marker (e.g. `text-pos/meaning-neg`, `harsh-words/flat-delivery`).
- `counterfactual`, `context-flip`, `mirror-prefix` (identical context turns of a mirror session), `context-dependent`.
- `hard-negative:<trap>` — looks like a trap label but isn't (sincere "sign today", "on board", negation, polite firmness…).
- `injection` — transcript text that tries to instruct the model; labelled by what the speaker actually means.
- `brief-pattern` — reworded variant of the brief's example tactic (enthusiastic commitment + third-party review);
  must carry ≥ 3 different labels across contexts. Never the brief's verbatim sentence.
- `sudden-shift`, `de-escalation`, `ultimatum`, `cold-aggression`, `blame`, `deflection:<kind>`, `baseline:<speaker type>`,
  `negation`, `concession-on-price`, plus a domain tag (`saas-renewal`, `procurement`, `pricing`, `competitor-bluff`, …).

Validate (no network, no model): `npx tsx apps/backend/eval/validate-dataset.ts` — needs `packages/contracts` built
(`npm run build`). Prints counts + coverage matrix; exit 1 on any error.
